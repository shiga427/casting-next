# キャスティング管制室 NEXT

インフルエンサー発掘・精査の管制室。**取得結果のファイルをドロップすると、その場で分析結果が画面に出ます。**
ビルド工程なしの静的SPA(vanilla JS + ES Modules)で、GitHub Pages にそのまま置けます。

- **コードは公開、データは各自のブラウザ。** 候補データ・精査メモは利用者のブラウザ(IndexedDB)と手元ファイルにしかありません。サーバに送信しません
- **取得は各自の Claude・各自の Instagram アカウント**で行います。DM送信・フォロー・いいね・投稿は一切しません
- 判定ロジックは現行の Python パイプライン(v2.7)と管制室 v1.4 からの**移植**です。新規発明はしていません

## ローカルで動かす

ES Modules を使うので `file://` では開けません。簡易サーバを立ててください。

```bash
cd casting-next
python3 -m http.server 8765
# → http://localhost:8765/ をブラウザで開く
```

1. 最初の画面でプロジェクト名を入れて「このブランドで始める」
2. 左の **収集(キューと依頼文)** を開く
3. `tests/fixtures/run6_compact.jsonl`(匿名化済みサンプル)をドロップ枠に落とす
4. その場で解析され、**分析結果**画面に切り替わります(機械合格13名・帯内35・落ち理由の内訳…)
5. **概要**と**候補ボード**にも同じデータが反映されます

## テスト

```bash
node --test tests/*.test.js      # 35件。CI(push時)でも同じものが回ります
```

| テスト | 何を保証するか |
|---|---|
| `golden_run6.test.js` | run#6 の匿名化fixtureで、**JS版の出力が Python版と1文字単位で一致**(全100件×拡張CSV25列)。機械合格13・帯内35・純度ゲート除外40・落ち理由12コード・シグナル36/7/15・語りの向き5/6/1/1 |
| `sbis_port.test.js` | 管制室 v1.4 の JSON を読み込み、**候補件数とSBIS採点が v1.4 と完全一致**(①〜⑤の内訳・純度減点・足切り・ハードゲート・基準移行ログの文言まで) |
| `qualsignals.test.js` | 定性シグナル抽出の回帰10件(営業導線は当事者性で相殺されない/「予約」単体は導線にしない ほか) |
| `analysis_view.test.js` | 分析結果画面に run#6 の実績値が出ること・A2アラートの発火 |

期待値は手書きではなく、移植元(Python / v1.4 HTML)を実際に実行して生成しています:

```bash
node tools/build_fixtures.mjs      # 匿名化fixtureを作る(reference/ が必要)
python3 tools/gen_run6_expected.py # 期待値を Python版パイプラインから作る
node tools/gen_v14_expected.mjs    # 期待値を 管制室v1.4 の採点コードから作る
node tools/e2e_smoke.mjs           # 実ブラウザでドロップ→分析結果までの通し確認+スクショ
```

## リポジトリに置かないもの

実在アカウントの取得データ・精査メモ・クライアント名入りの設定は**1バイトも置きません**(`.gitignore` で二重に防護)。
`tests/fixtures/` のデータは、ハンドル置換と数値摂動で匿名化したうえで、
**判定が1件も変わらないこと**を検証してから生成しています(`tools/build_fixtures.mjs`)。
