# キャスティング管制室 NEXT

インフルエンサー発掘・精査の管制室。**取得結果のファイルをドロップすると、その場で分析結果が画面に出ます。**
ビルド工程なしの静的SPA(vanilla JS + ES Modules)で、GitHub Pages にそのまま置けます。

- **コードは公開、データは各自のブラウザ。** 候補データ・精査メモは利用者のブラウザ(IndexedDB)と手元ファイルにしかありません。サーバに送信しません
- **取得は同梱の Casting Next 拡張(`extension/`)**が、各自の Chrome とログイン中の Instagram アカウントで行います。書き込み操作は**候補ボードでチェックした候補へのDM送付だけ**で、フォロー・いいね・投稿はしません(設計書_DM自動一括送付 §0)
- 判定ロジックは現行の Python パイプライン(v2.7)と管制室 v1.4 からの**移植**です。新規発明はしていません

> **⚠ 全自動送信は実現できません（2026-08-04 実機検証で確定）。**
> 設計書§5-3 が前提にしていた `POST /api/v1/direct_v2/threads/broadcast/text/` は、
> 現行の Instagram web に**存在しません**。実際に叩くとJSONではなくログインページが返り、
> セッションが切れます。人が手で送ったDMをネットワーク層で観測しても、
> このエンドポイントへのPOSTは**65件中0件**でした（実際は `/api/graphql` の Relay ミューテーション）。
> 残る手段はモバイル私設API（§5-3・§10 で禁止）だけなので、**半自動が上限**です。
> 半自動＝拡張が下書きまで入れ、**送信ボタンは人が1クリック**。文面生成・ガード・重複防止・
> レート制御・監査ログはすべてそのまま効きます。

## ローカルで動かす

ES Modules を使うので `file://` では開けません。簡易サーバを立ててください。

```bash
cd casting-next
python3 -m http.server 8765
# → http://localhost:8765/ をブラウザで開く
```

1. 最初の画面でプロジェクト名を入れて「このブランドで始める」
2. 左の **収集(発掘と取得)** を開く。手持ちのリストが無い人は既定の
   **「① 発掘から始める」**タブで探索タグを選ぶ（選んだ時点で拡張へ渡ります）
3. `tests/fixtures/run6_compact.jsonl`(匿名化済みサンプル)を取り込み枠に落とす
   （実運用では拡張が収集を終えるとここに**自動で入ります**）
4. その場で解析され、**分析結果**画面に切り替わります(機械合格13名・帯内35・落ち理由の内訳…)
5. **概要**と**候補ボード**にも同じデータが反映されます。
   同時にプール・取得済み台帳・探索カバレッジ表も更新され、2周目は「② プールから取得」が使えます

## 拡張(収集ツール)の入れ方

収集は同梱の Chrome 拡張が行います。ビルド不要です。

1. `chrome://extensions` を開き「デベロッパーモード」をオン
2. 「パッケージ化されていない拡張機能を読み込む」→ このリポジトリの `extension/` を選ぶ
3. instagram.com にご自身のアカウントでログインしておく
4. ダッシュボードのタブを開いたまま、拡張ポップアップの ①発掘して収集 / ②プールから取得 / ③精査データ を押す

ダッシュボード ↔ 拡張の受け渡しは localStorage の3キー
(`castnext_cdp_discover` / `castnext_cdp_queue` / `castnext_cdp_qual`)。
結果は拡張が Downloads に保存し、**ダッシュボードのファイル入力へ自動注入**して取り込みます。

## リポジトリに置かないもの

実在アカウントの取得データ・精査メモ・クライアント名入りの設定は**1バイトも置きません**(`.gitignore` で二重に防護)。
`tests/fixtures/` のデータは、ハンドル置換と数値摂動で匿名化したうえで、
**判定が1件も変わらないこと**を検証してから生成しています(`tools/build_fixtures.mjs`)。
