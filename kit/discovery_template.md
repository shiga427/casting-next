あなた(Claude)へのお願いです。**①タグから候補アカウントを集め、②そのまま数値の取得まで**行って、

## 禁止事項(最優先・1つでも破らないでください)

- **DM送信・フォロー・いいね・投稿・コメントを絶対にしない。** 閲覧と fetch だけです
- **UA(ユーザーエージェント)偽装をしない。** モバイル専用エンドポイントへの迂回もしません
- **ページ遷移を最小限に。** 遷移すると `window.IGF` が消えます(注入したスクリプトはタブのメモリ上にしかないため)
- `computer` 操作(クリック・スクロール)は最終手段。基本はページ内 fetch だけで完結します
- **集めたハンドルは1件も捨てない。** 除外ではなく「後回し」にします(収集の原則)

## 準備

1. **instagram.com のタブを開く**(ご本人のアカウントでログイン済みであること)
2. 次の2つを取得して、**そのまま**(1文字も変えずに)評価する
   - `{KIT_URL}/ig_probe.js` → `window.IGF` が定義されます
   - `{KIT_URL}/prof_compact.js` → `window.__PROF` と `window.__CAP` が定義されます
   - 評価後、`window.__CAP` の値を報告してください。**140未満なら中止**して報告(キャプションが短いと
     定性判定の引用が拾えず、判定が実力より低く出ます)
   - `window.__PRRE` が定義されていることも確認してください

## ① 発掘(タグから候補ハンドルを集める)

対象タグ(この順で回してください。上にあるものほど優先度が高い):

{TAGS}

各タグについて、次を評価します。

```js
const res = await IGF.hashtag('<タグ>');     // 例: IGF.hashtag('#アラサー美容')
```

返ってきた投稿から、**投稿者のハンドル**と**その投稿のいいね数**を控えてください。
いいね数は、取得前にフォロワー数が分からないための代理指標です(後で並べ替えに使います)。

集めたハンドルは次の規則で整理します。

1. **複数のタグに跨って出現したハンドルを最優先**(横断数が多いほど上)
2. 次に**生活文脈タグ(上の一覧で「生活」と付けたもの)由来**を優先
3. 次に**投稿いいね数 100〜8,000 のもの**(この窓の外は後回し。8,000超は有名人・大型メディア、100未満は休眠/ナノ帯)
4. いいね数が取れなかったものはその次
5. 次のいずれかに当てはまるハンドルは**最後尾に回す**(捨てない)
   - ハンドルに `official` `shop` `store` `salon` `clinic` `cosmetics` `magazine` `academy` `corp` などの法人語を含む
   - 大手ブランド名・媒体名そのもの(chanel / dior / shiseido / canmake / lips / muji / voce など)
   - 美容外ジャンル語(music / anime / game / idol / kpop など)を含む
   - ただし `ayaka_official` のように**人名が読み取れるもの**は法人扱いにしない

## ② 取得(集めたハンドルのプロフィールと直近投稿)

①で並べ替えた上位から **{TARGET}件**を目標に、次の形で取得します。

```js
const handles = [ /* ①の順に並べたハンドル */ ];
const out = await IGF.profileBatch(handles.slice(0, 20), 4000, 12000);   // 15〜20件ずつ
for (const res of out) {
  window.__R.push(__PROF(res, '<そのハンドルを見つけたタグ>', 'E1:<そのハンドルを見つけたタグ>'));
}
```

- **`__PROF` の第2引数にタグ、第3引数に `E1:タグ` を必ず入れてください。**
  この2つが、管制室側でプール・取得済み台帳・探索カバレッジ表を自動更新する材料になります
  (複数タグに跨るハンドルは `#タグA|#タグB` のように `|` で繋いでください)
- **15〜20件ごとに** `JSON.stringify(window.__R.splice(0))` をダンプして保存してください(1レコード ≒ 1.8KB)

## ペースとエラー処理

- リクエストの間には**4〜12秒**の間隔を置いてください(`profileBatch` が自動で待ちます)
- HTTP 429 や rate limit の兆候が出たら、**即中断して件数を報告**してください
  (取り直しは管制室がキューを作り直します。取得済みは自動で除外されるので重複しません)
- `schema_error` が出たら、**同一セッション内でプローブを再注入してから再取得**してください
  (run#6 では 20/20 件がこの手順で復旧しました)
- 1周目で取れなかったアカウントは、必ずもう一度だけリトライしてください

## データの規則

- フィードの返却順は投稿日時順ではありません。**`taken_at` の降順に整列してから直近12件**を確定してください
- サロゲート単体(壊れた絵文字)は除去してください
- キャプションが欠けている投稿があっても、それは Instagram 側の仕様です。欠けた旨を注記してください

## 30件時点の中間チェック

30件取得した時点で、フォロワーが **{BAND_MIN}〜{BAND_MAX}** の帯に入るアカウントが**5件未満**なら、
**中断して報告**してください(タグ選定の失敗に{TARGET}件分の取得を費やさないためです)。
