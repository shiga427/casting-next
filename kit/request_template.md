# Instagram プロフィール取得のお願い({RUN_TAG} / {COUNT}件)

あなた(Claude)へのお願いです。以下の {COUNT} 件の Instagram アカウントについて、
**公開プロフィールと直近投稿の数値**を、注入したプローブの fetch だけで取得し、JSONL で返してください。

## 禁止事項(最優先・1つでも破らないでください)

- **DM送信・フォロー・いいね・投稿・コメントを絶対にしない。** 閲覧と fetch だけです
- **UA(ユーザーエージェント)偽装をしない。** モバイル専用エンドポイントへの迂回もしません
- **ページ遷移を最小限に。** 遷移すると `window.IGF` が消えます(理由:注入したスクリプトはタブのメモリ上にしかないため)
- `computer` 操作(クリック・スクロール)は最終手段。基本はページ内 fetch だけで完結します

## 手順

1. **instagram.com のタブを開く**(ご本人のアカウントでログイン済みであること)
   - 理由:ページ内 fetch には Cookie / CSRF / App-ID が自動で乗るため、ログイン済みタブが必要です
2. 次の2つを取得して、**そのまま**(1文字も変えずに)評価する
   - `{KIT_URL}/ig_probe.js` → `window.IGF` が定義されます
   - `{KIT_URL}/prof_compact.js` → `window.__PROF` と `window.__CAP` が定義されます
   - 評価後、`window.__CAP` の値を報告してください。**140未満なら中止**して報告(理由:キャプションが短いと
     定性判定の引用が拾えず、判定が実力より低く出ます)
   - `window.__PRRE` が定義されていることも確認してください(PR表記を全文で判定するための正規表現です)
3. 対象ハンドルごとに、次を順に評価して結果を貯める
   ```js
   const res = await IGF.profile('<handle>');
   window.__R.push(__PROF(res, '<tags>', '<src>'));
   ```
4. **15〜20件ごとに** `JSON.stringify(window.__R.splice(0))` の結果をダンプして保存
   - 理由:1レコード ≒ 1.8KB。まとめて出すと1回の応答に収まりません

## ペースとエラー処理

- リクエストの間には**数秒の間隔**を置いてください(理由:短時間に連続すると制限がかかります)
- HTTP 429 や rate limit の兆候が出たら、**即中断して件数を報告**してください
  (取り直しは管制室がキューを再生成します。取得済みは自動で除外されるので重複しません)
- `schema_error` が出たら、**同一セッション内でプローブを再注入してから再取得**してください
  (run#6 では 20/20 件がこの手順で復旧しました)
- 1周目で取れなかったアカウントは、必ずもう一度だけリトライしてください

## データの規則

- フィードの返却順は投稿日時順ではありません。**`taken_at` の降順に整列してから直近12件**を確定してください
- サロゲート単体(壊れた絵文字)は除去してください
- キャプションが欠けている投稿があっても、それは Instagram 側の仕様です。欠けた旨を注記してください
